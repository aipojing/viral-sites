# AI 赛博判官（03）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成一个有硬成本和内容安全边界的 AI 判词站：用户提交昵称与可选简介，Worker 经校验、限流、预算预留、模型调用、结构校验和双重过滤后返回可保存判词；任何上游失败都能安全降级到本地审核过的兜底判词。

**Architecture:** `sites/ai-judge` 保存主站 `/ai-judge/` 玩法源码以及可独立测试的 AI handler，但不拥有部署入口；`sites/home` 懒加载前端，并由唯一主站 Worker 将 `/api/ai-judge/*` 分发给该 handler。模型通过小型 provider adapter 调用，KV 只缓存安全判词 24 小时，Durable Object `JudgeGate` 原子管理每日预算预留和每日身份次数，Rate Limiting binding 作为外层宽松防滥用；静态资源、Umami、未知 API 和部署均由主站 Worker 负责。

**Tech Stack:** Vite 8 · React 19 · TypeScript(strict) · Tailwind 4 · Vitest 3 · Cloudflare Workers Static Assets · Durable Objects · KV · Workers Rate Limiting binding · Web Crypto · Canvas 2D · `@viral/shared`

## Global Constraints

- 依据 `docs/03-ai-judge.md`；01/02 发布与工厂管线稳定后才允许生产部署。
- 遵守 [统一主站接入与单服务部署计划](2026-08-08-unified-home-integration.md)；生产页面固定 `/ai-judge/`，API 固定 `/api/ai-judge/verdict`，不得创建第二个 `wrangler.jsonc`、Worker 服务或 deploy script。
- 昵称必填、最多 12 Unicode code points；简介可选、最多 40；输入和输出均按 NFC 归一化。
- 判词 schema 固定：crime≤8、verdict 60～90、sentence≤24、seal≤16；前后端都验证，前端不信任 Worker JSON。
- 生成内容只调侃输入者自己的行为习惯，禁止外貌、地域、性别、疾病、家庭、政治、公众人物、仇恨、威胁、自伤和真实第三方攻击。
- schema 失败最多重试一次；安全过滤失败、超时、上游错误、预算暂停都不重试轰炸模型，直接使用审核过的 fallback 或明确熔断页。
- AI LLM key、HMAC secret、告警 webhook 只以 `AI_` 前缀存入主站 Worker secrets。仓库不提交真实 key；前端 bundle 不含 provider endpoint 的认证信息。
- KV cache key 是归一化输入的 SHA-256/HMAC 摘要，不保存原始输入；缓存值只保存已通过输出过滤的 Verdict，TTL 24h。页面明确 AI 请求会发送到所选模型提供方并说明缓存时限。
- 不建立跨站指纹。每日身份由 Worker 内对 `IP + 客户端随机 daily id` 做 HMAC 得到；只在 DO 当日对象内保存摘要和次数，次日换对象自然失效。
- 初始目标单次成本 `<¥0.02`、日预算 `¥50`；价格和模型不可写死在业务代码，使用部署变量并由 provider 实测记录冻结。
- 卡片使用横排仿公文版式：罪名大字 + 朱红大印是签名元素；不使用难读的整卡竖排。
- v1 明确不做头像上传、历史记录和付费重判；生产判断同时观察 `generate/save_image/fallback_used/rate_limited/budget_paused`，不以增加重判次数掩盖内容质量问题。

```ts
export class JudgeGate extends DurableObject<AiJudgeEnv> {
  authorize(identityHash: string): Promise<{ ok: true } | { ok: false; reason: 'rate_limited' }>
  reserveBudget(maxCostFen: number): Promise<ReserveResult>
  settle(reservationId: string, actualCostFen: number): Promise<void>
  cancel(reservationId: string): Promise<void>
}

type ReserveResult =
  | { ok: true; reservationId: string; budgetRatio: number }
  | { ok: false; reason: 'budget_paused'; budgetRatio: number }
```

- [ ] **Step 1: 写失败测试**

同一 identity 每日 authorize 仅 3 次；cache hit 也占次数但不占预算；并发预算预留不超上限；cancel 只释放预算、不回退身份次数；settle 以实际成本替换预留；跨 UTC+8 日期使用新 DO name；预算 80% 告警一次、100% 拒绝；storage 重启状态保留。

- [ ] **Step 2: 实现原子 storage transaction**

每个日期使用 `env.AI_JUDGE_GATE.idFromName(dateKeyUTC8(now))`。状态保存 `spentFen/reservedFen/identityCounts/reservations/alerted80`；reservation 15 分钟过期并在下一次请求清理。identityHash 使用 `HMAC(AI_IDENTITY_SECRET, ip|dailyId|dateKey)`，不保存原文。

- [ ] **Step 3: 实现 80% webhook**

DO 只发送日期、预算比例、请求计数，不发送输入、identity hash 或判词。webhook 失败不回滚已完成请求，但保持可重试的 `alerted80=false`。
