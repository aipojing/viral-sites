# 执行提示词（交给外部编码模型）

> 用法：把下面代码块内的全文粘贴给执行模型（qwen-code / Codex / 其他 CLI agent），工作目录设为仓库根。

```text
你是一名严格遵循 TDD 的资深前端工程师。你的任务是在本地仓库
/Users/ahs/Documents/vibe-coding/viral-sites
中，逐字执行一份已经写好的实现计划。计划已包含每一步的测试代码、实现代码和命令，你的职责是忠实执行、验证、提交，而不是重新设计。

## 第一步：按顺序读这些文件
1. docs/plans/2026-08-04-factory-and-life-grid.md —— 唯一执行依据，共 16 个任务
2. docs/01-life-grid.md —— 产品设计文档（理解你在做什么）
3. docs/00-factory-design.md 与 docs/00a-style-map.md —— 背景与视觉规范
任何冲突以实现计划为准；计划自身有歧义时停下报告，不要自行猜测。

## 执行规则（逐条遵守）
- 严格按 Task 1 → Task 15 顺序执行，不跳过、不合并、不重排。
- TDD 铁律：每个任务先写计划给出的失败测试 → 运行确认失败 → 写计划给出的实现 → 运行确认通过 → commit。禁止先写实现再补测试。
- 计划中每个「Run:」命令逐条执行，输出与「Expected:」比对；不符时先排查环境与拼写，再排查实现。
- 测试失败时修实现、不改测试。只有当测试与设计文档明显矛盾时才允许停下报告，等待人类裁决。
- 每完成一个任务立即用计划给出的 commit 信息提交，一个任务一个 commit，不加任何 Co-Authored-By 尾注。
- 计划中的色值是「方格作业本」视觉风格（纸白 #f7f4ec、铅笔灰 #8c8678、批改朱红 #c8392b、格线底），逐字使用，禁止「优化」成你偏好的配色。

## 禁止事项
- 禁止修改 docs/ 下的任何设计文档与计划文档
- 禁止引入计划未列出的依赖、组件库、日期库
- 禁止重构或「顺手改进」计划之外的代码
- 禁止 git push（只做本地 commit，push 由人类确认后执行）
- 禁止伪造测试通过或跳过失败的测试继续

## 停止点
- Task 16 的 Step 3（umami 账号）与 Step 4（wrangler login 部署）需要人类账号授权。
  你执行到「Task 15 全部完成 + Task 16 Step 1 体积核验通过」即停止，输出报告等待人类。
- 任何问题同一原因连续尝试 3 次仍失败：停止，报告已完成进度、卡点现象、你尝试过的方案。

## 最终验收（结束前自查，必须全绿）
- pnpm -r test 全部通过
- pnpm -r typecheck 零错误
- pnpm --filter @viral/life-grid build 成功，且构建输出中 JS + CSS 的 gzip 合计 < 100KB
- git log --oneline 显示每个已完成任务各有一个 conventional commits 格式的提交

## 完成报告格式
逐任务列出：任务号 / 状态（完成、跳过+原因、卡住+详情）/ commit 哈希 / 新增测试数。
最后给出：总测试数、typecheck 结果、构建体积（gzip）、与计划的全部偏差及原因（理想情况是「无偏差」）。

环境：macOS，已安装 node 与 pnpm；缺什么依赖用 pnpm 安装。现在开始，从读计划文件做起。
```
