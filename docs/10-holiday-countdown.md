# 10 · 放假倒计时（A 级）

> 2026-08-04 · 状态：设计完成，排队 · 形态：纯前端，年度数据驱动
> 注意：本站是「搜索常青 + 热点脉冲」型，考核指标与工厂默认的保存率不同（见 §7）

## 1. 一句话

距离下一个法定节假日还有 X 天——外加调休真相（「名义放 3 天，实际净赚 1 天」）和请假攻略（「请 3 休 8」），每逢调休公布必有一轮全网骂街，本站常驻接流。

## 2. 传播机制

- **搜索常青**：「还有几天放假」「2027 放假安排」是稳定搜索词，全年有底流量
- **热点脉冲**：每年 11~12 月国务院公布次年安排时的调休骂街，和每个长假前的「攻略转发潮」
- **转发动机**：调休锐评文案截图 + 请假攻略实用转发（「转给要请假的同事」）
- **对标**：竞品多但普遍糙（站长工具风）；差异化 = 调休锐评的梗浓度 + 请假攻略算法 + 工厂级质感

## 3. 页面结构

```
主屏：距下个假期的大数字倒计时 + 假期名 + 调休真相一句话
次屏：全年假期总览表（每个假：名义天数 / 调休上班日 / 净赚天数）
攻略区：每个长假的最优请假方案（「10.9~10.11 请 3 天，连休 8 天」）
```

- 调休真相文案是本站的「梗资产」：每个假期一条锐评（「五一：放五天，还四天，堪称假期理财产品」），配置化，每年随新安排更新
- 「距离下一个不调休的周末」彩蛋条目（调休上班的周末被扣掉），骂街情绪的精准出口

## 4. 数据与算法

- 年度数据 JSON：`{ 假期名, 起止日, 调休上班日[], 锐评文案 }`——数据源为国务院办公厅通知，**每年 11~12 月人工更新一次**（设日历提醒，这是本站唯一的运营义务）
- 请假攻略算法（`lib/leave-optimizer.ts`，纯函数）：给定假期起止 + 前后两周的周末与调休上班日，枚举「请 N 天（N≤4）」的所有方案，输出连休天数最大化的方案列表——有单测价值的小算法，边界（调休上班日恰在假期前后）要覆盖
- 倒计时显式传入 `now`，时区固定 UTC+8

## 5. 分享卡片

- 「我的假期余额」年览卡：今年剩余假期列表 + 总净赚天数 + 一句锐评 + 品牌条
- 长假前自动切换为「XX 假期攻略卡」（倒计时 + 最优请假方案），蹭假前转发潮

## 6. 技术要点

- 纯前端；数据 JSON 与文案分离；构建期校验数据（日期合法、调休日不在假期内）
- SEO 是本站少见的真实渠道：标题带年份关键词（「2026 放假安排 · 还有几天放假」），语义化日期标记；虽然海外托管对百度不友好，但本站值得把 SEO 基本功做满（白送的都要）

## 7. 埋点与考核（特殊）

- 标准三事件保留，但本站生死指标是：**周复访率**（常驻工具属性）+ **热点期日访问峰值**（调休公布日、长假前一周）
- `save_image` 预期偏低，不以保存率判死刑；攻略区加 `plan_viewed` 事件看实用功能渗透

## 8. 测试

- leave-optimizer 单测：典型年份全假期回归 + 调休边界 + 无解情形（假期孤立无周末可拼）
- 倒计时跨年、假期当天、最后一个假期过后（指向明年占位）边界单测
- 数据 lint 构建期跑

## 9. 风险

| 风险 | 应对 |
|------|------|
| 次年数据没及时更新，站变僵尸 | 每年 11 月 1 日日历提醒 + 页面自带「数据截至」标识；过期 30 天自动显示「等官方通知」态 |
| 竞品同质化 | 锐评梗浓度 + 攻略算法是壁垒；竞品不做文案只做数字 |
| 调休锐评被指「引导负面情绪」 | 只吐槽制度安排不涉具体机构；文案过一遍尺度审（骂调休可以，阴阳怪气适度） |
