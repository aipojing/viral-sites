# 04 · 上班回本计算器（备选池）

> 2026-08-04 · 状态：设计完成，待触发 · 形态：纯前端，工作日复访工具
> 触发条件：前三发验证量产管线后，需要补充「办公室场景」与复访型样本时启动

## 1. 一句话

把上班时间实时换算成工资等值：「今天已经回本 ¥187.43」「这个会开掉了你 ¥45」——让每一段难熬的时间至少看得见回报。

## 2. 产品定位与差异化

同类产品通常只有一个不断跳动的工资数字，看十秒就失去理由。本站把它设计成工作日可反复打开的「上班计价器」：

- **常驻价值**：今天赚了多少、离下班还有多久，适合固定标签页
- **互动价值**：给开会、带薪发呆、排队等具体片段计价
- **传播价值**：片段结束后生成一张不暴露月薪的荒诞小票
- **情绪边界**：替打工人把时间换成可见回报，不鼓励消极怠工，也不教育用户热爱工作

它承担的是工厂的「复访型工具」实验，不以一次性保存率与测试站直接横比。

## 3. 用户流程

### 3.1 首次设置（30 秒内）

1. 输入月薪，并选择口径：税前 / 到手；两种口径只用于标签说明，不做税务换算
2. 选择每周工作天数、每天带薪时长和上下班时间
3. 设置午休是否计入带薪时间；默认不计
4. 预览计算口径后进入今日面板

### 3.2 每日使用

- 上班前：显示「距离今天开始回本还有 X 分钟」
- 工作中：今日工资等值按秒增长，副信息显示离下班时间与剩余工资等值
- 午休或自定义非带薪时段：金额暂停，文案说明原因
- 下班后：金额停止，出现今日小结与「明天继续」
- 非工作日：默认显示「今天不替工资打工」，允许手动开启「今天也上班」临时班次

### 3.3 片段计价

用户点击一个场景开始计时：开会、带薪如厕、发呆、排队、临时自定义。结束后显示持续时间与工资等值，可保存片段小票或继续下一段。

同一时间只能有一个片段运行；片段金额属于今日工资的切片，不能再加到今日收入上，避免重复计算。

## 4. 计算口径与展示

- 小时工资按用户输入的月薪、每周工作天数和每日带薪时长换算为**估算等值**
- 今日金额只在配置的带薪区间增长；跨午休、跨午夜和临时加班都有明确状态
- 月薪本身不代表按时计件收入，页面固定写「这是时间等值，不是工资单或劳动报酬结算」
- 显示保留两位小数制造实时感，展开口径时同时显示未取整的时薪与工作安排
- 标签页在后台不持续重绘，回到前台后按真实时间差补算；计时事实不能依赖动画帧数

不显示「超过全国 X%」等无数据依据的工资或摸鱼排名，也不把用户工资上传去换 percentile。

## 5. 页面结构

```
今日面板：今日工资等值大数字 / 下班倒计时 / 当前状态
快捷计价：开会 / 如厕 / 发呆 / 排队 / 自定义
片段结果：时长 + 工资等值 + 小票卡
今日小结：已工作时长 / 片段时间分布 / 是否保存日报
设置与隐私：修改口径 / 隐藏金额 / 清除本地数据
```

首页提供一键「隐私模式」：金额立即模糊，只保留计时。再次显示金额需要主动点击，防止用户在办公室投屏或同事靠近时泄露薪资。

## 6. 分享卡片与视觉

视觉采用热敏收银小票拟物，签名元素是结束片段时从页面下方「打印」出一张锯齿边小票。动效只在出单瞬间出现，减少动态效果时直接展示。

### 6.1 片段小票（默认分享物）

- 场景名、持续时间、工资等值
- 一句克制锐评，例如「这个会至少值两杯奶茶的时间」
- 日期可选显示，月薪和时薪默认永不出现
- 品牌条

### 6.2 今日日报（次要）

包含今日总等值与片段占比，可能被反推薪资，因此默认关闭分享。用户开启时先看到隐私提示，并可选择隐藏总金额、只显示时间分布。

不使用真实品牌商品价格做自动比较；若后续增加「相当于几杯奶茶」，价格必须让用户自行设置或使用明确标注的示意值。

## 7. 本地数据与隐私

- 月薪、作息、片段记录全部只保存在浏览器本地
- 埋点只记录功能枚举与时长桶，不记录金额、时薪、上下班时间或自定义场景文本
- 首次设置页和页脚明确写「工资不会上传」
- 提供「仅本次使用」「长期保存在本机」两个选项，以及一键清除
- 分享卡生成前再次检查是否包含可反推工资的字段

## 8. 埋点与成功标准（复访型口径）

- `setup_completed`：完成首次设置，对应工厂标准 `generate`
- `scene_started` / `scene_finished`：只带场景 id 和时长桶
- `privacy_mode_used`
- `daily_summary_viewed`
- `save_image`：带 `card: scene | daily`
- D1 / D7 复访与每周活跃天数

一级指标是复访而不是保存：D1 ≥25%、D7 ≥10%、回访用户每周打开 ≥2 天、至少 30% 完成设置的用户使用过片段计价。片段小票保存率 ≥8% 即有传播价值；不要求达到工厂一次性站点的默认爆款阈值。

## 9. 测试与异常状态

- 覆盖上班前、工作中、午休、下班后、非工作日、临时加班和跨午夜班次
- 修改工资或作息后，历史片段保留当时等值还是按新设置重算：正式决策为**保留当时结果**，并标记口径日期
- 页面后台数小时再回来，金额补算正确且不耗电持续渲染
- 清除数据后工资、设置、历史片段和草稿全部消失
- 卡片长数字、超长自定义场景和隐私隐藏状态需做排版压力测试

## 10. 风险与启动 gate

| 风险 | 应对 |
|------|------|
| 与现有工资计时器同质化 | 片段计价、小票卡、隐私模式和日报构成完整工作日闭环 |
| 工资换算被当成真实结算 | 全程称「工资等值」；口径可展开；不提供税务或劳动争议结论 |
| 输入敏感，用户不敢填 | 本地计算、仅本次模式、一键隐藏与清除、卡片默认隐藏工资 |
| 新鲜感过后不再回来 | 用 D1/D7 验证；不靠新增场景掩盖无复访 |
| 片段命名被理解为鼓励怠工 | 默认文案偏自嘲，不做公司/老板攻击，不设计「摸鱼排行榜」 |

启动前只保留一个外部检查：快速复核当时同类产品仍提供什么，确保片段计价和隐私卡片有真实差异。产品决策本身已经闭合；若冷启动渠道没有稳定办公室受众，或原型测试中用户普遍拒绝输入工资，则继续留在备选池。
