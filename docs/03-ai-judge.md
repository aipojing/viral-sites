# 03 · AI 赛博判官（第三发）

> 2026-08-04 · 状态：设计完成，待实现 · 形态：前端 + Cloudflare Workers 代理 LLM
> 前置条件：01/02 已上线且管线稳定，再引入「接口成本」与「内容安全」两个新变量

## 1. 一句话

报上昵称和一句话自我介绍，AI 判官当庭宣判：一张仿古判词卡，毒舌、好笑、字字扎心——「快看它怎么骂我哈哈哈」是中文互联网最强的转发动机之一。

## 2. 传播机制

- **情绪钩子**：被冒犯的快感（自嘲）+ 好笑 + 每个人结果都不同（个性化内容天然抗审美疲劳）
- **转发动机**：晒判词（「它怎么知道我是这样的人」）+ 拉人受审（「你也来领一张」）
- **对标**：AI 算命 / AI 嘴替 / 毒鸡汤生成器都各自爆过；判官 + 判词卡的「公文美学」是形式差异化

## 3. 用户流程

```
公堂落地页（惊堂木一拍的仪式感）
→ 输入：昵称（必填，≤12 字）+ 一句话自我介绍（可选，≤40 字）
→ 「升堂」按钮 → 生成中动效（判官提笔，2~5 秒）
→ 判词卡（罪名 + 判词正文 + 刑期梗 + 保存按钮）
```

v1 明确砍掉：头像上传（引入存储与肖像隐私问题）、历史记录、重判次数购买。YAGNI。

## 4. 判词结构（LLM 输出契约）

LLM 按 JSON 结构化输出，前端渲染成卡片：

```
Verdict {
  crime:    string   // 罪名，如「拖延成瘾罪」，≤8 字
  verdict:  string   // 判词正文，60~90 字，毒舌但见血、有具体细节
  sentence: string   // 刑期梗，如「判处早睡三个月，缓期执行（大概率）」，≤24 字
  seal:     string   // 印章小字，如「赛博衙门 · 即日生效」
}
```

Prompt 设计原则（实现期打磨，此处锁边界）：

- 毒舌对象只能是**输入者本人的行为习惯**，禁止涉及外貌、地域、性别、疾病、家庭
- 有梗有细节，不用「你就是这样的人」式空话；从昵称/简介里抓具体线索
- 输出必须是合法 JSON，schema 校验失败自动重试一次，再失败走兜底判词库（预写 20 条通用判词，保证用户永远拿得到结果）

## 5. 后端架构（Cloudflare Workers）

前端不碰 LLM key，所有请求经 Workers 代理：

```
浏览器 → Workers（校验/限流/缓存/预算） → LLM API → 结构化判词 → 浏览器渲染卡片
```

- **模型**：便宜量大的档位（候选：DeepSeek / Haiku 级别，实现期按当时价格与中文梗能力实测二选一），单次成本目标 < ¥0.02
- **限流**：IP + 浏览器指纹，每天 3 次/人（重判稀缺性本身是产品设计：判词更值得保存）；超限文案「本官今日已阅卷过多，明日再来」
- **缓存**：相同输入（昵称+简介归一化后 hash）直接返回缓存判词，防脚本刷量
- **预算熔断**：Workers 内计数，日成本达上限（初期 ¥50/天）后进入「衙门下班」模式——文案化的暂停服务页，绝不静默烧钱。爆量是幸福的烦恼，熔断页本身也要好玩到可截图
- **密钥**：LLM key 仅存于 Workers secret；仓库只有 `.env.example` 占位

## 6. 内容安全（上线硬门槛）

- **输入过滤**：昵称/简介过敏感词表（政治、真实公众人物姓名、辱骂性词汇）；命中则温和拒绝：「本官不审此案」
- **输出过滤**：判词过同一敏感词表 + 禁止类目复查（外貌/地域/性别/疾病/家庭），命中则丢弃并走兜底判词库
- **页面声明**：「判词由 AI 生成，纯属玩梗，不构成对任何人的评价」
- **红线**：用户输入他人姓名来「代审」无法完全防住，靠 prompt 约束（判词只针对行为不针对身份）+ 输出过滤兜底；如上线后出现恶意用法案例，加「只能审自己」的声明与更严过滤

## 7. 判词卡视觉

- 竖版仿古判牍：米黄纸纹底、朱红印章、判词竖排或仿公文横排（实现期出两版选一）
- 罪名大字是卡片的视觉锤，缩略图里一眼可读
- 走 `shared/share-card` 管线，底部品牌条同工厂标准

## 8. 埋点与成本监控

- 标准三事件：`visit` / `generate`（判词返回成功）/ `save_image`
- 本站特有：`rate_limited`（限流触发）、`budget_paused`（熔断触发）、`fallback_used`（兜底判词）——三个都是运营信号
- Workers 侧每日成本写入 KV，超过 80% 预算时通过邮件告警（Cloudflare Email Workers 或简单 webhook）

## 9. 测试

- Workers 单测：限流逻辑、缓存 hash 归一化、预算计数、schema 校验与兜底切换
- Prompt 回归集：固定 20 组输入（含敏感词攻击样本、超长输入、emoji 昵称），人工评审输出是否越界，作为每次改 prompt 的回归清单
- 前端：判词渲染纯函数单测 + 四环境保存路径手工验收

## 10. 风险

| 风险 | 应对 |
|------|------|
| 爆量 → 成本失控 | 日预算熔断（¥50 起步，手动调）+ 限流 + 缓存，三层防线 |
| 输出越界（骂过头/涉敏感） | 输入输出双过滤 + 禁止类目 + 兜底判词库 + 回归集 |
| LLM 接口不稳定 | 兜底判词库保证可用性；接口超时 8 秒即切兜底 |
| 玩法被快速抄袭 | 必然的；壁垒在 prompt 打磨出的「梗质量」与判词卡质感，抄得走形式抄不走味道 |
