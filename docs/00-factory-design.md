# 00 · 小站工厂总体设计

> 2026-08-04 · 状态：已定稿（随实践迭代）

## 1. 背景与目标

做一批「功能极简、好玩、易传播」的中文小网站。目标按优先级排序：

1. **验证传播**：找到至少一个能自传播的点子（用户主动保存/转发，而不是靠投放）
2. **沉淀流量**：把爆款流量导入可持续的阵地（域名复访、公众号/小红书号）
3. **变现**：有稳定流量后再谈（导流、赞助位、付费增强），验证期不考虑
4. **练手**：流水线本身就是工程练习的价值

## 2. 核心判断（一切设计的出发点）

- **命中率极低**：viral 是彩票，单点 all-in 是赌博，批量试错是策略。工厂的意义在于把单次试错成本压到 1~2 天。
- **图能传，链接传不动**：微信对外链不友好、小红书不给外链、抖音靠截图。所以每个站的核心交付物是**一张让人愿意保存的结果卡片**，卡片上带站名，让图片自己把流量带回来。
- **质感是传播力的一半**：同样的点子，做得糙就是地摊货，做得精致才有转发的「社交货币」价值。宁可少做功能，不能省视觉。
- **情绪是燃料**：扎心、好笑、可炫耀，三选一，最好占两个。没有情绪钩子的工具只有搜索流量，没有传播。

## 3. 工厂流水线

### 3.1 上新 SOP

```
点子 → 一页纸设计（半天） → 开发（1~2 天） → 上线 + 埋点
     → 冷启动投放（朋友圈/群/小红书发一轮） → 观察 7 天 → 决策
```

决策标准（核心指标：**保存率 = 保存卡片数 ÷ 访问数**）：

| 保存率 | 判定 | 动作 |
|--------|------|------|
| < 1% | 没有传播力 | 归档，不再投入 |
| 1% ~ 5% | 有苗头 | 迭代文案/卡片一轮，再观察 7 天 |
| > 5% | 爆款候选 | 买域名、深耕、加玩法、考虑变现 |

辅助指标：完成率（进结果页的人数 ÷ 访问）、7 日复访。指标不达标但主观判断有潜力的，最多再给一轮迭代，避免恋战。

### 3.2 热点快反（吸收 C 方案）

流水线跑顺之后，蹭热点的边际成本会降到一天内。热点工具不单独立项，作为工厂的机会主义产出：热点出现 → 套模板 → 24h 内上线。判断标准同上，但观察期缩短到 3 天（热点流量衰减快）。

## 4. 技术架构

### 4.1 Monorepo 结构

```
viral-sites/
  packages/
    shared/               # 共享能力，唯一允许被 sites 依赖的包
      src/
        share-card/       # 分享卡片：canvas 渲染 + 保存适配
        analytics/        # 第一方产品事件采集
        ui/               # 移动端优先的基础组件（按钮/输入/布局）
  sites/
    life-grid/            # 01 人生进度条
    mental-state/         # 02 精神状态检测
    ai-judge/             # 03 AI 赛博判官
    ...                   # 每个点子一个独立 Vite app
```

- pnpm workspace；玩法之间**零依赖**，只允许依赖 `shared`；唯一生产组合层是 `sites/home`
- 技术栈：Vite + React + TypeScript + Tailwind（熟手栈，不引入学习成本）
- 玩法源码各自独立开发测试；生产只由 `sites/home` 统一 Vite MPA 构建、单一 Cloudflare Worker 部署（见下 §4.4）

### 4.2 共享能力一：分享卡片（工厂核心资产）

职责：把站点给的「卡片数据」渲染成一张可保存的图。

- **规格**：默认 3:4 竖版（1080×1440），适配朋友圈九宫格与小红书；底部固定品牌条（站名 + 域名文字；有正式域名后加二维码）
- **渲染**：canvas 离屏渲染，站点提供绘制回调，shared 负责导出、缩放、设备像素比处理
- **保存适配**（中文环境的三个坑，一次解决处处复用）：
  - 微信内置浏览器：不能触发下载 → canvas 转 `<img>` 覆盖展示，提示「长按图片保存」
  - iOS Safari：同走长按保存路径
  - 桌面浏览器：`canvas.toBlob` + a[download] 直接下载
- **降级**：canvas 导出失败（罕见的内存/污染问题）→ 提示用户手动截图，并上报 `export_error` 事件

### 4.3 共享能力二：埋点（工厂的眼睛）

- 工具：主站 Worker 同源接收 `/api/events`，写入 Cloudflare Analytics Engine；运行错误单独进入 Workers Logs
- `track(event, data?)` 薄封装：使用匿名 sessionStorage 会话标识，优先 `sendBeacon`、降级 `fetch keepalive`，失败静默且不影响玩法
- **事件规范**（所有站统一，便于横向对比）：
  - `page_view`：进入站点，由统一入口自动上报
  - `generate`：生成结果（= 完成核心流程）
  - `save_image`：保存/长按查看卡片（= 传播意向，核心指标分子）
  - 站点可加自定义事件，但这三个必须有且语义一致
- 隐私边界：不记录 IP、完整 User-Agent、昵称、输入正文和问答内容；Worker 只接收事件白名单及固定维度

### 4.4 部署

- **统一主站单一部署**：只有 `sites/home` 是生产应用（Vite MPA 输出 `/` 与 `/<玩法>/`），由一个 Cloudflare Worker（Static Assets）提供服务；不再为玩法新建 Pages/Workers 项目
- 玩法地址是同源路径（如 `/ai-judge/`、`/salary-timer/`），禁止 iframe、禁止外部子站 URL；`sites/<玩法>` 的独立 `build` 仅作模块自检，产物不得发布
- 历史验证期 `*.pages.dev` 站点保留只读，不再更新
- 需要后端的玩法（AI 判官、按住不放）走同一个主站 Worker 的命名空间 API（`/api/ai-judge/*`、`/api/hold-button/*`），绑定与 secrets 只在 `sites/home/wrangler.jsonc` 声明

## 5. 变现路径（验证期不做，仅记录方向）

1. **导流**：卡片/站内挂公众号或小红书号，把一次性流量变成粉丝（优先级最高，最不伤体验）
2. **赞助位**：单站流量稳定后接品牌赞助（参考「摸鱼办」模式）
3. **付费增强**：高级卡片皮肤、去水印、批量生成等轻付费
4. 明确不做：弹窗广告、诱导分享、信息收集

## 6. 合规与风险

| 风险 | 应对 |
|------|------|
| 海外托管无备案，微信内可能提示风险/被封域名 | 验证期接受；爆款站买多个域名做轮换预案；重要站再评估备案+国内部署 |
| 国内访问 `*.pages.dev` 速度不稳定 | 站点体积压到极小（首屏 < 100KB），静态资源内联；爆款再上自定义域名 + 优化 |
| 百度对海外中文站收录差 | 不指望 SEO，流量策略以社交传播为主；SEO 是白送的才要 |
| 用户隐私 | 所有输入（生日、工资等）只在浏览器本地计算，不上传不存储；埋点不带个人数据。这也是可以写在页面上的信任卖点 |
| AI 类站点的内容安全与成本 | 见 [03-ai-judge.md](03-ai-judge.md)，限流 + 预算熔断 + 输入输出过滤 |
| 点子撞车（别人已做过） | 撞车不可怕，做得糙才可怕；差异化永远在文案 + 质感 |
