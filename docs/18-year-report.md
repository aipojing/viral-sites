# 18 · 年度报告生成器（B 级 · 简版设计）

> 2026-08-04 · 状态：待触发 · 触发条件：节令件，每年 11 月启动、12 月中旬上线
> 形态：纯前端，翻页 H5 + 模板美学

## 1. 一句话

App 们都给你发年度报告，谁给你的「人生本体」发一份？手动回答 10 个问题（今年最远去了哪 / 最常点的外卖 / 哭过几次），生成一份仿流媒体美学的「我的 2026 年度报告」翻页 H5 + 总结卡。

## 2. 传播机制

年度报告是 12 月已被各大 App 验证到烂的顶级传播形态（网易云刷屏是现象级案例）；本站钻的空子是：**App 只能总结它看得到的数据，人生的大部分没有 App 记录**。手填内容 = 完全个性化 + 回答本身是一次年度回顾的情绪仪式。B 级原因：强节令 + 制作重（翻页动效美学是硬门槛，做糙不如不做）。

## 3. 玩法要点

- 10 问设计（答题即回忆，题目要能勾起具体画面）：今年去过最远的地方 / 重复听最多的歌 / 今年认识的最重要的人 / 哭过几次笑过几次（滑块）/ 年初 flag 完成度（滑块）/ 给今年打分
- 输出双形态：
  - **翻页 H5**（6~8 页，仿流媒体年度报告的节奏与动效）——本站的质感担当，链接可转发
  - **总结卡**（一页浓缩版）——保存传播担当
- 明年复用：模板不变换年份文案，第二年边际成本近零（节令件里少有的可复利资产）

## 4. 技术要点

- 全部本地：答案不上传（年度报告涉私密，本地化明示是信任卖点，同工厂隐私原则）
- 翻页 H5 用 CSS scroll-snap + 轻动效实现，不引重型动画库（首屏预算内）；文字排版是美学主战场，字体子集内联
- 答案编码进 URL 可选项（让翻页 H5 可被转发查看）——复用 06 的编码方案，但涉私密答案，**默认关闭**，用户显式勾选「生成可分享链接」才编码

## 5. 埋点与启动前问题

- 标准三事件 + 完答率（10 问流失点）+ H5 链接打开数（若开启分享）
- 启动前回答：12 月流量竞争极烈（所有 App 都在发报告），冷启动投放排期要卡在大厂报告发布潮**之前**（12 月上旬）还是蹭潮（中旬）？届时看当年日历定
